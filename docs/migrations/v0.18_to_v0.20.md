# Migration: v0.18 → v0.20

## Headline

- 33 named recipes across 5 clusters (was 8 in v0.18).
- `vstack-dashboard` HTML dashboard with dark-mode rendering.
- `vstack-recipes` CLI for terminal browsing.
- Recipe catalog gains a `cluster` field.

## What changed

### Added: 25 new named recipes

The catalog expanded from 8 → 33 recipes. New recipes:
hallucination_cascade, sycophancy_drift, over_apology_loop,
silent_dependency_drop, refusal_cascade, context_saturation,
blame_spiral, motivation_collapse, plan_collapse,
premature_completion, tool_misuse, anxious_overhedge,
silent_dependency_drop, handoff_loss, consensus_dilution,
deference_cascade, expert_loafing, cold_handoff,
performative_empathy, decision_paralysis, bottleneck_orchestrator,
hub_spoke_fragility, role_thrash, espoused_actual_drift,
policy_decay, hyper_specialization, overconfidence_spiral.

Each ships with a multi-pattern bundle that targets a specific
failure mode. Browse via:

```bash
vstack-recipes list
vstack-recipes show <name>
vstack-recipes list --cluster reasoning
```

### Added: cluster field

`Recipe` instances now carry a `cluster` field. Five clusters:
**reasoning** / **coordination** / **trust** / **workload** /
**culture**.

```python
from vstack.diagnose import RECIPES, list_recipes_by_cluster

reasoning = list_recipes_by_cluster("reasoning")
for r in reasoning:
    print(r.name, r.description)
```

### Added: `vstack-dashboard`

Production HTML dashboard with dark-mode rendering and FastAPI
serving:

```bash
vstack-dashboard render --report report.json > report.html
vstack-dashboard serve --port 7878
```

`DiagnoseReport` now has a `.to_html()` method:

```python
from vstack import diagnose
report = diagnose(trace=trace, llm_client=llm)
html = report.to_html(report_id="run-001", title="My Report")
```

The dashboard render module is at `vstack.dashboard` (production
import: `from vstack.dashboard import render_report,
DashboardConfig`).

### Added: `vstack-recipes` CLI

Terminal browser for the recipe catalog. Subcommands:

```bash
vstack-recipes list                       # list all
vstack-recipes list --cluster trust       # by cluster
vstack-recipes list --shape team          # by shape
vstack-recipes list --q sycophancy        # substring search
vstack-recipes match "agents disagreeing" # free-text router
vstack-recipes show stuck_in_loop         # show one recipe
vstack-recipes show stuck_in_loop --md    # markdown output
vstack-recipes show stuck_in_loop --json  # JSON output
```

## Required code changes

### Recipe filtering by cluster

If you were iterating `RECIPES.values()` and expected a flat list,
the new `cluster` field is a no-op (additive). To filter by
cluster, use `list_recipes_by_cluster`:

```python
# Before (still works):
trust_recipes = [r for r in RECIPES.values() if "trust" in r.name]

# After (recommended):
from vstack.diagnose import list_recipes_by_cluster
trust_recipes = list_recipes_by_cluster("trust")
```

### Dashboard rendering

If you were rendering reports manually with Jinja templates, the
new `vstack.dashboard.render_report()` does this for you:

```python
# Before (manual):
import jinja2
template = jinja2.Template("...")
html = template.render(report=report)

# After (built-in):
from vstack.dashboard import render_report
html = render_report(report)
```

The manual approach still works but the built-in renderer is
maintained and matches the canonical dashboard CSS.
